# 边缘节点下板：树莓派 2B（ARMv7）跑 device + 网关

> 目的：把链路**南向两层**（device + gateway）搬到一块 ARM 边缘节点上，用 systemd 托管，
> 并把"真机直读 / 断网补传 / 崩溃自愈 / 重启自启"四条在真实硬件上验一遍。
> 取证日期：2026-10-22 · 证据见 `docs/evidence/edge-arm-20261022/`

---

## 一、为什么是这两层，不是全栈

| 层 | 跑在哪 | 理由 |
|---|---|---|
| device（:5020，真机直读） | **边缘节点** | 串口在这块板子上；容器拿不到宿主串口 |
| gateway（采集 / 断网缓存 / 补传） | **边缘节点** | 断网自治的载体，必须在现场 |
| EMQX / TDengine / 接入层 / web / nginx | **平台侧**（x86 宿主） | 按时序库、broker、展示的定义属平台侧；1 GB 内存的 2B 也跑不动 |

拓扑：

```
[温湿度变送器] --RS485--> [树莓派 2B · cems-edge]
                            cems-device      :5020  （直读 /dev/ttyUSB0，1 号炉 2 个点）
                            cems-gateway-plant1      从站 1 → MQTT
                            cems-gateway-plant2      从站 2（纯仿真）→ MQTT
                                  | MQTT 1883（百兆网口）
                                  v
                            [x86 宿主 192.168.31.18]
                            EMQX → 接入层 → TDengine → web / nginx
```

## 三、烧卡与首次开机

脚本：`deploy/raspi/flash_card.ps1`（Windows，管理员）+ `deploy/raspi/provision_edge.sh`（板子上跑）。

```powershell
# Windows 管理员 PowerShell；先确认目标盘是 USB、≥ 7 GB、不是系统盘
.\deploy\raspi\flash_card.ps1 -ImageFile C:\tmp\pi-lite.img.xz -DiskNumber 4 `
    -UserName ddf -Password '<临时口令>' `
    -ExpectedImageSha256 340d17e344724aebe42f5ca7d16fa569d99a64ceb9304942b551defed4edc4b9
```

脚本做四件事：解压并校验镜像 → 校验目标盘（只允许 USB、非 boot/system、≥ 6 GB）→ 写盘 →
在 boot 分区建 `ssh` 空文件与 `userconf.txt`（预置用户与口令哈希），**免显示器开机即通 SSH**。

```bash
# 首次开机后（网线 + 5V 2A micro-USB 电源），从 Windows：
ssh ddf@cems-edge.local "hostname; uname -m"     # 期望 cems-edge / armv7l
scp deploy/raspi/provision_edge.sh ddf@cems-edge.local:~/
ssh ddf@cems-edge.local "bash ~/provision_edge.sh"
```

`provision_edge.sh` 会设时区、装 `python3-venv`、建 `~/cems/.venv`、装 `requirements-edge.txt`、
检查 `/dev/ttyUSB0` 并做一次只读 RTU 冒烟测试。

## 四、服务托管（systemd）

单元文件在 `deploy/systemd/`，三个服务：`cems-device` / `cems-gateway-plant1` / `cems-gateway-plant2`，
全部 `Restart=always`（进程退出即拉起）+ `Type=notify` / `WatchdogSec=60`（采集循环每圈发 `WATCHDOG=1`，
超时未发 = 活着但不出数，systemd 杀掉重启）、日志走 journald。

心跳实现在 `src/common/sd_notify.py`：没有 `NOTIFY_SOCKET` 时是 **no-op**，所以普通
`python -m src.device.modbus_server`、容器、单元测试都不受影响，不需要开关。

```bash
sudo bash deploy/systemd/install.sh --repo /home/ddf/cems --user ddf --platform-host 192.168.31.18
systemctl is-enabled cems-device cems-gateway-plant1 cems-gateway-plant2
```

> ⚠️ 平台侧 broker 必须能从板子访问。本次在 x86 宿主上把 EMQX 的 1883 绑到 `0.0.0.0`；
> **其余端口（TDengine / nginx / web / 管理台）应保持 `127.0.0.1`**，见 `README.md` §端口暴露 / 安全。

## 五、实测结果（2026-10-22）

| # | 项 | 结果 | 证据 |
|---|---|---|---|
| 1 | **真机直读** | 每 2 s 一次：湿度 **56.6~56.7 %RH**、温度 **25.6 degC**、状态位 0；无一次读失败 | `02-serial-read.txt`（日志段）、`07-e2e-tdengine.txt` |
| 2 | **端到端入库** | TDengine `device1` 的 `temp`/`humidity` 是环境真值（25.6 / 56.8~57.3），真机在线期间非空行 **840** 条；同库 `device2` 仍是烟气仿真值（207 / 44） | `07-e2e-tdengine.txt` |
| 3 | **重启自启** | `reboot` 后三个服务无人工介入自动 active；三个 unit `enabled` | `04-boot-autostart.txt`、`03-systemd-units.txt` |
| 4 | **崩溃自愈** | `kill -9` 主进程 → systemd 拉起（PID 433→790，`NRestarts=1`），另外两个服务不受影响，重启后自动补传 1 条 | `05-crash-recovery.txt` |
| 5 | **断网补传** | 停 broker 90 s：网关缓存 **25 条**；broker 恢复后 `[补传完成] broker 已确认 25 条`，`cache.jsonl` 归零；`device2` 近 6 分钟 **71 行**（期望 72，差 1 行为窗口边界） | `06-broker-outage-resend.txt` |
| 6 | **资源足迹** | 常驻 RSS：device **19.2 MB**、网关各 **21.4 MB**；CPU 合计 **< 2.5%** | `09-resources.txt` |
| 7 | **真机失效语义** | 拔掉 485（USB 断开）：连续读失败、状态位=1、对外写越界值、**不回落到仿真**；库里 `device1` 的 `temp`/`humidity` 变成 **NULL**（不是 0、不是假数据） | `12-485-absent-stale.txt`、`07-e2e-tdengine.txt` |
| 8 | **应用级看门狗** | `Type=notify` + `WatchdogSec=60`，采集循环每圈发 `WATCHDOG=1`。`kill -STOP` 冻结主进程（模拟"进程活着但循环卡住"）→ 60 s 后 `Watchdog timeout (limit 1min)!` → `SIGABRT` → 自动重启（PID 883→905，`NRestarts=1`），重启后继续出数 | `13-watchdog-sigstop.txt` |

> 第 4、5 条是验收时现场做的：kill 是 `kill -9` 主 PID；断网是停掉平台侧 EMQX 容器 90 s
> （等价于"broker 不可达"，比拔网线少一个变量），恢复后按缓存条数逐条对账。

## 六、边界（本次**没有**覆盖的）

| # | 边界 | 说明 |
|---|---|---|
| 1 | ⚠️ **看门狗只覆盖"循环卡住"** | `Type=notify` + `WatchdogSec=60` 能抓"进程活着但采集循环不转了"（读挂死、线程死锁）。**抓不到**"循环在转但值是假的"这类语义问题 —— 那要靠越界值/质量位那条链路 |
| 2 | ⚠️ **断电自愈未验证** | `reboot` 验过；直接断电（非正常关机）没测，SD 卡上可能留损坏文件 |
| 3 | ⚠️ **MQTT 无认证** | broker 只靠网络边界；板子到 broker 的 1883 目前是匿名可写 |
| 4 | ⚠️ **供电欠压** | `vcgencmd get_throttled = 0x50005`：换线后仍报欠压+降频，长期跑有随机卡死与 SD 损坏风险，需换 5V 2.5 A 电源 |
| 5 | ⚠️ **SD 卡写寿命** | 网关缓存文件落在 SD 卡上（正常运行时 `cache.jsonl` 为空，只在断网时写）；未做写放大测量 |
| 6 | ⚠️ **ARM 上只跑了南向两层** | web / 接入层 / 时序库仍在 x86；"整栈上 ARM"未验证 |
| 7 | ⚠️ **无 RTC** | 2B 没有硬时钟，首次启动时间来自 fake-hwclock，联网后由 NTP 校正（`last` 里会看到假的旧日期） |
| 8 | ⚠️ **只测一组串口参数** | 4800/8/N/1、从站 1；其它波特率/校验组合未测 |
| 9 | ⚠️ **单串口单设备** | 一条 485 总线只挂了一台变送器；多从站真实直读未测 |

## 七、复现命令（从拿到板子到跑通）

```bash
# 0) 板子上：依赖
sudo apt-get update && sudo apt-get install -y python3-venv python3-pip
python3 -m venv ~/cems/.venv
cp requirements-edge.txt ~/cems/
~/cems/.venv/bin/pip install -r ~/cems/requirements-edge.txt

# 1) 同步代码（仓库在该机上不是 git 仓库时）
#    Windows: tar -C <repo> -czf - src deploy requirements-edge.txt | ssh ddf@cems-edge.local "tar -C ~/cems -xzf -"

# 2) 冒烟：只读探针（不占 TCP 端口）
cd ~/cems && .venv/bin/python -m src.device.rtu_master --port /dev/ttyUSB0 --count 5

# 3) 装 systemd 单元
sudo bash deploy/systemd/install.sh --repo /home/ddf/cems --user ddf --platform-host <平台侧 IP>

# 4) 自检
systemctl is-active cems-device cems-gateway-plant1 cems-gateway-plant2
journalctl -u cems-device -n 20 --no-pager        # 应有"串口直读：湿度 x %RH ｜ 温度 y degC ｜ 状态位=0"
```

**预期**：三个服务 active；device 日志每 2 s 一条真机读数；平台侧 TDengine 里 `device1` 的
`temp`/`humidity` 是环境值，`device2` 仍是仿真值。
