# 物理层取证（Modbus RTU over RS-485）

> 目的：在**物理层**留下可复核的证据，补上本仓库此前只在代码层/日志层取证的缺口。
> 设备：RS485 温湿度变送器（项目 1 的真机），从站 `0x01`，功能码 `03`。
> 工具：Saleae 兼容 8 通道逻辑分析仪（24 MHz，克隆版）+ Logic 2。
> 取证日期：2026-10-18

---

## 一、接线

```
USB-RS485 转换器
   ├── A ────────┬── 变送器 A
   │             └── 逻辑分析仪 CH1
   ├── B ────────── 变送器 B
   └── G ────────┬── 逻辑分析仪 GND
                 └── （不接变送器；见 §5 边界）

逻辑分析仪其余 7 个通道悬空；
转换器的 TR 端子悬空（终端电阻，短距离不用）。
```

⭐ **逻辑分析仪的 GND 接「转换器的 G」**，不接变送器电源负 —— 因为分析仪的 GND 经 USB 连到主机地，与转换器同源，参考电位一致。

⚠️ **接前用万用表确认 A 对 G 在 0~5 V 之间**（分析仪输入上限 5 V）。

---

## 二、器材与软件设置

| 项 | 值 |
|---|---|
| 逻辑分析仪 | Saleae 兼容 8 通道，24 MHz |
| 软件 | Logic 2 |
| 采样率 | ⚠️ **1 MS/s**（24 MS/s 会 ReadTimeout，见 §4） |
| 采样时长 | 2 秒 |
| 通道 | `D0`（对应 CH1） |
| 解码器 | Async Serial（UART） |
| 波特率 | **4800** |
| 帧格式 | **8 数据位 / 无校验 / 1 停止位** |
| 位序 | LSB first |
| 信号反相 | 否 |

⭐ 采样率取 **1 MS/s** 的依据：4800 baud 下每 bit 宽 **208 μs**，1 MS/s 相当于**每 bit 约 208 个采样点**，余量充足。

## 三、结果

### 3.1 两帧原始字节（波形解出）

```
请求：01 03 00 00 00 02 C4 0B
响应：01 03 04 02 37 00 F9 8A 07
```

**请求解析**：从站 `0x01` / 功能码 `03`(读保持寄存器) / 起始地址 `0x0000` / 数量 `0x0002`

**响应解析**：

| 域 | 值 | 含义 |
|---|---|---|
| 字节数 | `0x04` | 4 个数据字节 |
| 数据 | `0x0237` | **567 → 湿度 56.7 %**（÷10） |
| 数据 | `0x00F9` | **249 → 温度 24.9 ℃**（int16 ÷10） |

### 3.2 ⭐ CRC 独立复算（关键）

用与设备代码**无关**的独立实现（多项式 `0xA001`，初值 `0xFFFF`，低字节先发）复算：

| 帧 | 被校验数据 | 算出 CRC | 波形解出 | 结论 |
|---|---|---|---|---|
| 请求 | `01 03 00 00 00 02` | `C4 0B` | `C4 0B` | ✅ 一致 |
| 响应 | `01 03 04 02 37 00 F9` | `8A 07` | `8A 07` | ✅ 一致 |

⭐ **两帧 CRC 全部一致** ⇒ 波形解出的字节序列**自洽且正确**，不是误码。

### 3.3 字节宽度（波特率实测）

| 项 | 值 |
|---|---|
| 理论：10 bit/字节（1 起始 + 8 数据 + 1 停止）× 208 μs | **2.083 ms** |
| 实测（Logic 2 `duration` 列） | **1.979 ms** |
| 误差 | **5.0 %** |

⭐ 实测与理论吻合 ⇒ **波特率确为 4800**，不是靠配置"声明"的。

### 3.4 帧间隔

两次请求间隔 **≈ 1 秒**，与主站轮询周期一致（见 `docs/evidence/physical-layer-20261018/03-request-and-response.png`）。

### 3.5 ⭐ 故障注入：拔掉 A 线

**做法**：主站在持续轮询的状态下，**拔掉 A 线**，同时观察物理层与应用层。

**物理层**（`07-fault-a-wire-pulled-bus-silent.png`）：
- CH1 夹在 A 上，**A 被拔掉后该通道失去信号源** → **波形全平，无任何跳变**。

**应用层**（`08-fault-a-wire-pulled-master-timeout.png`）：

```
[1335] 湿度 57.9 %  温度 24.5 C   ← 最后一次成功
[1336] 读失败: Modbus Error: [Invalid Message] No response received,
              expected at least 4 bytes (0 received)
[1337] 读失败: Modbus Error: [Input/Output] No Response received
              from the remote slave/Unable to decode response
[1338] 起持续失败
```

| 现象 | 值 |
|---|---|
| 连续成功次数 | ⭐ **1335 次** |
| 失败起点 | ⭐ **第 1336 次**（= 拔线时刻） |
| 首次失败形态 | `Invalid Message`，**收到 0 字节** |
| 之后形态 | `Input/Output`，`Unable to decode response` |

⭐ **两种错误形态的差别**：首次失败发生在拔线瞬间，总线上还残留过渡波形，主站判为"消息不完整"；此后总线彻底静默，判为"无响应/无法解码"。

⚠️ 本轮只拔了 A 线，**未做**错波特率、CRC 错帧等其它注入形态（见 §5）。

## 四、过程中踩到的坑（如实记录）

⚠️ **首次采集报 `ReadTimeout`**：采样率设为 **24 MS/s** 时，USB 传输跟不上，采集中断。

**处置**：降到 **1 MS/s** 解决。

⭐ 结论：**4800 baud 的信号不需要高采样率，1 MS/s 已有约 208 倍过采样。**
证据：`docs/evidence/physical-layer-20261018/06-pitfall-readtimeout-24MSs.png`

## 五、边界（这次**没有**验证的）

| # | 边界 | 说明 |
|---|---|---|
| 1 | ⚠️ **故障注入只做了一种** | 已做**拔 A 线**（§3.5）；未做**错波特率**、**CRC 错帧** |
| 2 | ⚠️ **只夹了单线 A** | 未做 A/B 差分的双通道对比 |

| 6 | ⚠️ **未测终端电阻的作用** | TR 端子悬空；短距离下不影响，长线需要 120 Ω |

## 六、复现步骤

```powershell
# 1. 接线（见 §1），确认 A 对 G 电压在 0~5 V
# 2. 让总线上有流量：跑最小主站轮询
python F:\Project1\_local\read_sensor.py COM3
#    期望输出：湿度 ~55.8 % / 温度 ~25.0 C，每秒一条

# 3. Logic 2：采样率 1 MS/s，时长 2 s，CH1(D0)
# 4. 加 Async Serial：Channel 0 / 4800 / 8N1 / LSB first
# 5. 停止采集后放大到单帧，核对字节与 CRC
```

⭐ **CRC 复算脚本**（与设备代码无关的独立实现）：

```python
def crc16_modbus(data: bytes) -> bytes:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return bytes([crc & 0xFF, (crc >> 8) & 0xFF])   # 低字节先发

assert crc16_modbus(bytes([0x01,0x03,0x00,0x00,0x00,0x02])) == bytes([0xC4,0x0B])
assert crc16_modbus(bytes([0x01,0x03,0x04,0x02,0x37,0x00,0xF9])) == bytes([0x8A,0x07])
```

## 八、这一步补了什么

**此前**：本仓库对采集链路的全部结论都建立在**代码层**（实现）与**日志层**（运行记录）之上。

**现在**：多了一条**物理层**证据 ——

> ⭐ **波形上解出的字节，与设备代码算出的 CRC 完全一致；字节宽度与 4800 baud 理论值吻合（误差 5 %）。**
> ⭐ **拔掉 A 线后：物理层全平，应用层从第 1336 次起持续超时 —— 断链在两层的表现都留了证。**

⇒ 说明"这条链路确实在用 4800/8N1 的 Modbus RTU 收发"，而**不是只在配置里这么写**；
并且在**断链时**，物理层与业务层都能各自体现出来。

⚠️ 但这**不等于**现场可用 —— 见 §5 的 7 条边界。
