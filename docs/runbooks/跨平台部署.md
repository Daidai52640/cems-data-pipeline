# 跨平台部署：Linux 宿主（离线镜像 + 宿主机 venv）

> 目的：在**非 Docker Desktop** 的 Linux 宿主上把整条链路跑起来，并留下一份可照着复现的步骤。
> 结果：4 个基础设施容器 + 4 个宿主机 Python 服务全部跑通，端到端有数据入库。
> 取证日期：2026-10-18 · 证据见 `docs/evidence/linux-deploy-20261018/`

---

## 一、为什么需要这份文档

仓库原有的部署说明默认 **Windows + Docker Desktop**（见 `离线部署验证.md` §8 的边界：
"跨平台：只在 Windows + Docker Desktop 上做过，Linux 宿主未验"）。

本次在 Linux 宿主上完整验证，并把两处**新的约束**写下来：

1. **Docker Hub 不可达**（`registry-1.docker.io` 连接被拒）→ **必须用离线镜像包**
2. **基础镜像 `python:3.12-slim` 拉不到** → **Python 服务改用宿主机 venv**

这两条不是环境瑕疵，是**国内离线/内网部署的常态**，值得写进文档而不是每次现场踩。

## 三、部署取舍：为什么是"容器 + 宿主机 venv"混合

| 组件 | 用什么跑 | 理由 |
|---|---|---|
| EMQX / TDengine / Redis | **容器** | 现成镜像；不自己维护中间件 |
| device / gateway / subscriber / web | **宿主机 venv** | ⚠️ **缺 `python:3.12-slim` 基础镜像**，且 Docker Hub 不可达 |

⭐ **这个组合等价于边缘设备的常见形态**：中间件用容器，业务进程由系统服务管理。
⚠️ 它与 README 里"统一用 Docker Compose 启动"的表述**不一致** —— 这是本次的实测偏差，已记入边界。

## 四、步骤

### 4.1 安装 Docker

```bash
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2
sudo usermod -aG docker "$USER"      # 生效需重新登录
```

> 用发行版包而非官方源：官方源需访问 Docker Hub，本环境不可达。

### 4.2 离线搬运镜像

镜像来自本仓库既有的离线导出包（`scripts/export_images.ps1` 的产物，662 MB）：

```bash
scp cems-images-*.tar <linux-host>:/tmp/
docker load -i /tmp/cems-images-*.tar
```

加载结果（实测）：

| 镜像 | 大小 |
|---|---|
| `emqx/emqx:6.3.0` | 484 MB |
| `tdengine/tdengine:3.3.6.13` | 1.47 GB |
| `redis:7.4.11-alpine` | 57.8 MB |
| `nginx:1.31.6-alpine` | 94.4 MB |
| ⚠️ `cems-pipeline:latest` | **2.27 kB**（见 §六 边界 1） |

### 4.3 起基础设施

```bash
docker compose up -d emqx tdengine redis
```

`docker compose ps` 实测（33 秒后全部 healthy）：

```
cems-redis   Up (healthy)   6379/tcp
emqx         Up (healthy)   127.0.0.1:1883, 18083
tdengine     Up (healthy)   127.0.0.1:6030, 6041
```

### 4.4 宿主机 venv

```bash
python3 -m venv .venv
.venv/bin/pip install -i https://mirrors.aliyun.com/pypi/simple/ -r requirements.txt
```

> `Dockerfile` 里已把 pip 源默认设为阿里云；宿主机安装沿用同一源。
> 实测：`pymodbus` / `paho` / `taosrest` / `flask` 均可导入。

### 4.5 启动 4 个 Python 服务

代码里的连接默认值就是 `localhost`（`TD_URL=http://localhost:6041`、`MQTT_HOST=localhost`、
`MODBUS_HOST=localhost`、`REDIS_HOST=127.0.0.1`），**因此在宿主机上无需额外注入环境变量**：

```bash
for p in src/device/modbus_server.py src/gateway/gateway.py \
         src/platform/subscriber_to_td.py src/web/web_dashboard.py; do
  setsid nohup .venv/bin/python "$p" > ~/cems-run/$(basename $p .py).log 2>&1 &
done
```

端口实测：`0.0.0.0:5020`（设备层）、`0.0.0.0:5000`（web）。

| 6 | ⚠️ **未接真实环保平台** | 与 `README.md` §已知边界 第 1 条一致，本次未改变 |
| 7 | ⚠️ **Docker Hub 不可达** | 后续若需新镜像，仍须走离线包或可用镜像源；本次未解决拉取通道 |
| 8 | ⚠️ **Windows 侧 Docker Desktop 未在本次使用** | 与本文件无关，但注意仓库的 `离线部署验证.md` 仍以 Docker Desktop 为前提 |

| 原边界 | 现状 | 出处 |
|---|---|---|

## 七、复现命令（从零到跑通）

```bash
# 0) 前置：Docker 已装、离线镜像包已 scp 到 /tmp
# 1) 加载镜像
docker load -i /tmp/cems-images-*.tar

# 2) 起基础设施并等健康
docker compose up -d emqx tdengine redis
until [ "$(docker compose ps --format '{{.Status}}' | grep -c healthy)" -ge 3 ]; do sleep 2; done

# 3) 宿主机依赖
python3 -m venv .venv
.venv/bin/pip install -q -i https://mirrors.aliyun.com/pypi/simple/ -r requirements.txt

# 4) 起业务进程
mkdir -p ~/cems-run
for p in src/device/modbus_server.py src/gateway/gateway.py \
         src/platform/subscriber_to_td.py src/web/web_dashboard.py; do
  setsid nohup .venv/bin/python "$p" > ~/cems-run/$(basename $p .py).log 2>&1 &
done

# 5) 自检
curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5000/
docker exec tdengine taos -s "select count(*) from cems.cems_data;"
```

**预期**：HTTP 200；`count(*)` 随时间增长（每 5 秒 1 条）。
