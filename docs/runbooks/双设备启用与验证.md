# 双设备（第二台设备）启用与验证

> **一句话**：第二台设备不是"改一个配置"，而是**两个开关**。
> **只开一个，不会报错 —— 但两台设备的数据会完全一样。**

---

## 1. 为什么是"两个开关"

| # | 开关 | 在哪 | 作用 |
|---|---|---|---|
| **开关 1** | **`SLAVE_IDS=1,2`** | 使用方 `.env`（**设备层**） | 让仿真设备**同时提供从站 1 与从站 2** |
| **开关 2** | **`--profile plant2`** | `docker compose` 命令行（**编排层**） | 让**第二套网关+接入实例**起来，去读从站 2 |

**为什么不能合并成一个**（设计取舍见 `docs/adr/0008-多设备多实例路线.md`）：
- 开关 1 属**设备层**（一条链路挂多台仪表，仿现场接线）
- 开关 2 属**编排层**（每台设备一套网关/接入实例）
- **两层独立**，且**默认值必须保持"单设备"**（否则既有验收脚本会把两条曲线混在一起看）

**⚠️ 代价（profiles 的固有坑）**：不带 `--profile plant2` 的
`docker compose stop` / `down` / `ps` **管不到第二套实例**。

---

## 2. ⚠️ 关键：只开一个会怎样

| 你只开了 | 现象 | 好发现吗 |
|---|---|---|
| **只开开关 2**（跑 `--profile plant2`，但没设 `SLAVE_IDS=1,2`） | ⚠️ **两台数据完全相同**：不报错、不缺数据、条数也正常（各 12 条/分钟）、**容器全 healthy** | ❌ **极难发现** |
| 只开开关 1（设了 `SLAVE_IDS=1,2`，没起第二套） | 从站 2 没人读 → **device2 没数据** | ✅ 容易发现（少一台） |

### 为什么会"完全一样"

设备层只有从站 1 时，plant2 网关（`MODBUS_UNIT=2`）**读的是一个不存在的从站**。
**实测**（临时服务端只建从站 1，分别读 unit 1/2/3）：

```
read unit=1 → OK  数据
read unit=2 → OK  数据   ← 从站 2 不存在，却拿到了从站 1 的数据
read unit=3 → OK  数据
```

**根因**：pymodbus 在 `single=True` 下会把**任何**请求的 unit id 改写成内部地址 0，
于是"请求不存在的从站"**成功返回**了那份唯一的数据块 —— **既不报错，也不是异常码**。

**→ 所以危险的不是"缺数据"，而是"看起来完全正常的错误数据"**，
它会污染下游：告警算错、两台曲线无差异、多设备演示价值归零。

> **⚠️ 2026-10-03 起的护栏**：设备层已改为**按 unit id 严格分派**（`single=False`），
> 请求未登记的从站会**收到异常响应**而不是别人的数据；网关也加了**启动预检**——
> 读不到本从站就 **拒绝启动**（容器直接红），CRITICAL 日志会直接点名"两个开关"。
> 但**验收仍必须做**（见第 4 节），因为护栏只保证"响亮失败"，不保证"你配对了"。

## 3. 正确启用步骤

```powershell
# ① 开关 1：设备层提供两个从站（写进使用方 .env，该文件不进版本库）
SLAVE_IDS=1,2
SLAVE_PHASE_OFFSET=10800        # 让两台曲线有相位差（可区分）

# ② 让开关 1 生效
docker compose up -d --force-recreate device

# ③ 开关 2：起第二套网关/接入实例
docker compose --profile plant2 up -d
```

**期望的日志证据**

设备层（`docker logs cems-device`）：
```
Modbus 仿真设备启动: 0.0.0.0:5020 从站=1,2（按 unit id 严格分派…）
从站1: 仿真种子=20261001 相位偏移=+0s
从站2: 仿真种子=20261002 相位偏移=+10800s
```

两个网关各自预检通过：
```
[gw1] 启动预检通过: 从站1 可读（9 个寄存器）
[gw2] 启动预检通过: 从站2 可读（9 个寄存器）
```

## 4. ⭐ 验收判据：**必须做"同一时刻逐值对比"**

> **不能只看"两台都有数据"** —— 那正是"镜像"状态的特征。

```powershell
# ① 设备数：应返回 2 个
docker exec tdengine taos -s "SELECT DISTINCT device FROM cems.cems_data;"

# ② ⭐ 同一时刻逐值对比：两台的读数必须【不同】
docker exec tdengine taos -s "SELECT ts, device, flow, so2, o2, temp FROM cems.cems_data WHERE ts >= NOW - 30s ORDER BY ts DESC LIMIT 6;"
```

**实测对照（判据长什么样）**

| 状态 | 同一 `ts` 的两台读数 |
|---|---|
| ❌ **镜像（踩坑）** | `flow 35938 / so2 29.1 / o2 6.9 / temp 200.2` —— **逐值完全相同** |
| ✅ **正常** | device1 `flow 35580 / o2 6.9 / temp 200.3`　device2 `flow 29617 / o2 7.7 / temp 209.2` |

**③ 全链路自检（两台各自）**
```powershell
python scripts/verify_pipeline_live.py --minutes 3 --device device1
python scripts/verify_pipeline_live.py --minutes 3 --device device2
```

**④ 采样率**（各应为 12 条/分钟 = 5 秒一条）
```powershell
docker exec tdengine taos -s "SELECT device, COUNT(*) FROM cems.cems_data WHERE ts >= NOW - 60s GROUP BY device;"
```

## 5. 关闭与回退

```powershell
# 关闭第二套（⚠️ 必须带 --profile，否则停不掉）
docker compose --profile plant2 down

# 完全回到单设备：把 .env 的 SLAVE_IDS 改回 1，并重建设备层
#   SLAVE_IDS=1
docker compose up -d --force-recreate device
```

**回退后的期望**：8 个基础容器、`SELECT DISTINCT device` 只返回 `device1`；
`SLAVE_IDS=1` 时设备层仍走单从站路径，**行为与改造前一致**。

---

## 6. 排障速查

| 现象 | 先查 |
|---|---|
| 两台数据完全相同 | **开关 1** 没开（`SLAVE_IDS` 缺第二个从站） |
| 第二套容器不出现 | 命令漏了 `--profile plant2` |
| `down` 停不掉第二套 | `down`/`stop`/`ps` 都要带 `--profile plant2` |
| plant2 网关**启动即退出**、CRITICAL | 启动预检拦下了：它读的从站不在设备层 `SLAVE_IDS` 里 |
| 只有 device1 有数据 | 开关 2 没开（第二套没起） |
| 多了台设备但报表/大屏看不到 | 展示层按 `plant/device` 过滤，该设备需要自己的实例或配置 |
