## 1. 启停

### 1.1 单设备（基础容器，默认 8 个服务）

```powershell
docker compose up -d --build
```

启动后浏览器打开 `http://localhost` 看实时曲线（经 nginx 反代）。
也可双击 `一键启动.bat`（就绪并确认 Web 能响应后自动打开浏览器，参数见 README）。

### 1.2 双设备（第二台设备 = 两个开关）

第二台设备不是"改一个配置"，而是**两个开关**，缺一不可：

1. `.env` 里设 `SLAVE_IDS=1,2`（设备层同时提供从站 1、2）；
2. `docker compose --profile plant2 up -d`（第二套网关 + 接入实例）。

**完整启用步骤、日志证据、逐值对比验收、回退方法见 [`双设备启用与验证.md`](双设备启用与验证.md)，本手册不展开。**

### 1.3 关闭

```powershell
docker compose down              # 停止并删除容器（数据保留在卷里）
docker compose down -v           # 停止并连数据一起删除
```

⚠️ **`down`（以及 `stop`、`ps`）不带 `--profile plant2` 管不到第二套实例**（`gateway2` / `subscriber2`）。
关闭第二套必须显式带 profile：

```powershell
docker compose --profile plant2 down
# 或只停第二套：
docker compose --profile plant2 stop gateway2 subscriber2
```

## 2. 健康检查

### 2.1 看容器状态

```powershell
docker compose ps                                          # 基础 8 个服务
docker compose --profile plant2 ps                         # 双设备时两套都列
docker compose ps --format "{{.Name}}`t{{.Status}}"        # 只看名称与状态列
```

STATUS 列期望 `Up … (healthy)`；出现 `unhealthy` / `restarting` / `Exited` 先按 §5 看日志。

### 2.2 ⭐ 健康不等于业务正常

容器 healthcheck 只证明**进程/端口/心跳**层面的事（例如接入层探的是能否连上 broker 1883、
网关探的是心跳文件新鲜度），**不证明数据在正常入库**。
`故障台账.md` 故障 1 / 2 / 3 都实测过"容器全部 healthy，但数据断了 / 不入库 / 配置写错"。

**数据新鲜度的唯一判据是 `GET /api/health`**（契约 C17："配置错误必须响亮：
非法 tag → 拒绝启动；数据不新鲜 → `/api/health` 503"）：

```powershell
Invoke-WebRequest http://127.0.0.1:5001/api/health
```

（5001 为 web 直连端口；经 nginx 入口 `http://localhost/api/health` 同样可访问。
注意 `/api/cache/*` 会被 nginx 挡成 403，见 §3。）

| 结果 | 含义 |
|---|---|
| HTTP **200**，`"ok": true`、`"reason": "fresh"` | 库连得上**且**数据新鲜 |
| HTTP **503**，`reason=td_unreachable` | 库不可达 |
| HTTP **503**，`reason=no_rows_last_1min` | 最近 1 分钟 0 条 |
| HTTP **503**，`reason=stale_data` | 最近一条样本距今超过阈值（默认 15 s） |
| HTTP **503**，`reason=unparsable_ts` | 最新时间戳无法解析 |

Web 容器自身的 healthcheck 就是按这个接口的 HTTP 状态码判成败（200 健康 / 503 不健康）。

## 3. 巡检项

| # | 查什么 | 命令 | 期望值 | 异常怎么办 |
|---|---|---|---|---|
| 1 | 各容器状态 | `docker compose --profile plant2 ps` | 基础 8 个 Up/healthy；双设备时共 10 个 | 异常容器按 §5 取日志 |
| 2 | 两台设备出数速率 | `docker exec tdengine taos -s "SELECT device, COUNT(*) FROM cems.cems_data WHERE ts >= NOW - 60s GROUP BY device;"` | 每台 **12 条/分钟**（5 秒一条） | 偏少/为 0：按 §6 常见问题定位 |
| 3 | 网关缓存（第一套） | `(Get-Content data\cache.jsonl \| Measure-Object -Line).Lines` | **0 行**（无积压） | 持续增长 = 补传不出去：§6 第 4 行 |
| 4 | 网关缓存（第二套） | `(Get-Content data\plant2\cache.jsonl).Count` | **0 行** | 同上，注意只看本实例目录 |
| 5 | 数据新鲜度 | `Invoke-WebRequest http://127.0.0.1:5001/api/health` | 200，`reason=fresh`，`data_age_seconds` ≤ 15 | 503：按 reason 对照 §2.2、§6 |
| 6 | 查询缓存统计 | `Invoke-WebRequest http://127.0.0.1:5001/api/cache/stats` | 返回命中率 / 查库次数 / 水位等计数 | 计数异常先看 web 与 redis 日志 |

巡检补充：
- 缓存文件正常应为空；断网期间会增长，恢复后排空。缓存容量上限 `CACHE_MAX_BYTES` 默认 **64 MB**（见 README）。
- `/api/cache/stats`、`/api/cache/clear` 必须走 **5001 直连**，nginx 默认把 `/api/cache/` 整个路径 `return 403`。
- 数据落地位置：TDengine 具名卷 `cems-tdengine-data`、EMQX `cems-emqx-data`；
  网关缓存分别在宿主机 `data/`（第一套）与 `data/plant2/`（第二套）。

| 项 | 数值 |
|---|---|
| 备份内容（主表 `cems_data`） | **18 570 行**（device1 15 990 + device2 2 580） |
| 逻辑备份产物 | **7.36 MiB**（41 个文件） |

补传/断档对账恒等式：

```
断开前基线 + 断开期间新产生 − 补传队列剩余 == 库内新增
```

## 5. 日志查看

通用用法：

```powershell
docker compose logs -f <服务名>          # 跟踪某个服务（服务名见下表左列）
docker logs <容器名> --tail 25           # 只看最近 25 行
```

| 服务（compose） | 容器名 | 取日志命令 |
|---|---|---|
| emqx | emqx | `docker logs emqx --tail 25` |
| tdengine | tdengine | `docker logs tdengine --tail 25` |
| device | cems-device | `docker logs cems-device --tail 25` |
| gateway | cems-gateway | `docker logs cems-gateway --tail 25` |
| gateway2（profile） | cems-gateway-plant2 | `docker logs cems-gateway-plant2 --tail 25` |
| subscriber | cems-subscriber | `docker logs cems-subscriber --tail 25` |
| subscriber2（profile） | cems-subscriber-plant2 | `docker logs cems-subscriber-plant2 --tail 25` |
| redis | cems-redis | `docker logs cems-redis --tail 25` |
| nginx | cems-nginx | `docker logs cems-nginx --tail 25` |
| web | cems-web | `docker logs cems-web --tail 25` |

**先看哪个容器（按现象判）**：

- **数据不新鲜 / 没数据**：先看 `cems-gateway`（双设备再看 `cems-gateway-plant2`）——
  日志直接给出 `连不上 Modbus 设备`（上游断）、`MQTT 连接断开`、`[缓存] 断网`（下游断）、
  `开始补传 / 补传完成`，能立刻分清断在哪一段。
- **网关日志显示已发、库里没有**：看 `cems-subscriber`（拒收累计、入库报错）。
- **浏览器 502 / 对外入口打不开**：看 `cems-nginx`。
- **查询/建库报错**：看 `tdengine`。

## 6. 常见问题

| 现象 | 先查什么 | 怎么办 |
|---|---|---|
| **两台数据完全一样** | 开关 1：`.env` 是否 `SLAVE_IDS=1,2`，改后是否 `docker compose up -d --force-recreate device` | 按 [`双设备启用与验证.md`](双设备启用与验证.md) §3 重开，并做 §4 的"同一时刻逐值对比"验收 |
| **device2 没数据** | 开关 2：`docker compose --profile plant2 ps` 看 `gateway2`/`subscriber2` 在不在 | 没起就 `docker compose --profile plant2 up -d`；启动即退出看网关启动预检日志 |
| **容器 healthy 但没数据** | 先 `Invoke-WebRequest http://127.0.0.1:5001/api/health` 看 `reason`，再看网关日志 | `连不上 Modbus` = 上游断（未采到，缓存救不了）；`[缓存] 断网` = 下游断（恢复后自动补传）；启动横幅/`docker inspect` 显示配置错 = 改回并重建（对应台账故障 1/2/3） |
| **网关补传不出去**（`cache.jsonl` 持续增长） | 先看 emqx 状态与 `docker logs emqx`，再看网关日志的 MQTT 报错 | emqx 没起/不健康 → 恢复 emqx；端口/主题/client_id 配错 → 改回重建（台账故障 1、故障 3）。恢复后缓存应归零 |
| **改代码后不生效** | 是否在非 `device` 的服务名上加了 `--build`（空操作） | 按 [`容器重建与代码生效.md`](容器重建与代码生效.md)：`docker compose build device` → `docker compose up -d --force-recreate device gateway subscriber web`，再比对容器内文件哈希 |

## 7. 阈值速查

| 项 | 值 | 出处 |
|---|---|---|
| 颗粒物限值（dust） | **5 mg/m3** | `src/common/points.py` Dust `limit=5.0` |
| SO2 限值（so2） | **35 mg/m3** | 同文件 SO2 `limit=35.0` |
| NOx 限值（nox） | **50 mg/m3** | 同文件 NOx `limit=50.0` |
| O2 基准（折算基准氧，火电燃煤） | **6.0 %** | `points.O2_REFERENCE = 6.0` |
| 折算公式 | **折算值 = 实测值 × 15 / (21 − O2)** | 即 `× (21−6)/(21−O2)`，`points.to_reference_o2()` |
| 超标判定 | **折算值 > 限值**（**等于限值算达标**） | 口径同 `src/common/alarm_judge.py` |
| 覆盖率门限 | **0.75**（低于判数据不足，不判达标/超标） | `REPORT_COVERAGE_MIN` / `ALARM_COVERAGE_MIN` 默认 0.75 |
| 采集周期 | **5 秒**（名义 12 条/min、720 条/h） | `POLL_INTERVAL="5.0"` |
| 数据新鲜度阈值 | **15 秒**（采集周期 × 因子 3） | `HEALTH_STALE_POLL_FACTOR` 默认 3 |
| 补传重试间隔 | **30 秒** | `RESEND_RETRY_INTERVAL="30.0"` |
| 断网缓存容量上限 | **64 MB** | `CACHE_MAX_BYTES` 默认 64MB（见 README） |

测点（共 **9 个**，顺序即 HJ 212 上传值序）：

| 列名 | 含义 | 单位 |
|---|---|---|
| flow | 烟气流量 | m3/h |
| dust | 颗粒物 | mg/m3 |
| so2 | 二氧化硫 | mg/m3 |
| nox | 氮氧化物 | mg/m3 |
| o2 | 氧含量 | % |
| velocity | 烟气流速 | m·s⁻¹ |
| temp | 烟气温度（代码单位 degC，展示为 ℃） | degC |
| humidity | 烟气湿度 | % |
| pressure | 烟气压力 | kPa |

端口（默认只绑定 `127.0.0.1`，需局域网访问在 `.env` 设 `BIND_ADDR=0.0.0.0` 并改掉默认口令）：

| 端口（宿主机） | 用途 |
|---|---|
| **80** | nginx，对外入口（`http://localhost`） |
| **5001** | web 直连（容器内 5000） |
| **1883 / 18083** | EMQX MQTT / Dashboard 管理台（默认 admin/public） |
| **6041 / 6030** | TDengine REST / 原生协议（演示口令 root/taosdata） |
| **5020** | 设备 Modbus TCP |
