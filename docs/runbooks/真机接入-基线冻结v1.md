## 3. 配置快照（`.env`）

⚠️ `.env` 被 gitignore —— **换机器不会带走，会静默退回纯仿真**。

```ini
SLAVE_IDS=1,2              # 设备层提供从站 1、2
REAL_DEVICE_ENABLE=1       # ★ 设备层混流：Temp/Humidity 改由真机供给
REAL_DEVICE_HOST=host.docker.internal
REAL_DEVICE_PORT=5021
REAL_DEVICE_UNIT=1
REAL_DEVICE_SLAVE=1        # ★ 只覆盖从站 1
```

**未在 `.env` 里、用代码默认值的**：
`REAL_DEVICE_POLL_INTERVAL=2.0`、`REAL_DEVICE_STALE_AFTER_FAILURES=3`

## 4. 数据链路（两条并存）

```
[温湿度变送器] --RS485--> COM3
                             |
              scripts/serial_bridge.py（宿主，Modbus TCP :5021）
                             |
        ┌────────────────────┴────────────────────┐
        |                                         |
   路径 A：设备层混流                        路径 B：点集分离
   （cems-device, REAL_DEVICE_ENABLE=1）      （gateway-transmitter, POINT_SET=transmitter）
   地址 6=Temp / 7=Humidity ← 真机            2 个测点 AirTemp/AirHumidity ← 真机
   其余 7 点仿真                              网关只读前 2 个寄存器
        |                                         |
   cems/plant1/data                          cems/transmitter/data
        |                                         |
   cems-subscriber → cems_data               cems-subscriber-transmitter → transmitter_data
        |                                         |
        └──────────────► 大屏（:5001）◄───────────┘
```

**实测一致**（2026-10-11 冻结时刻）：
```
桥   : [614, 260, 0, 86]        （0=湿度×10, 1=温度×10, 2=状态, 3=累计失败数）
设备层: reg6=260 → 26.0 degC ｜ reg7=614 → 61.4 %
cems_data.plant1_device1      : 14:55:04 | 26.0 | 61.4
transmitter_data.transmitter_tx01 : 14:55:04 | 26.0 | 61.4
```

## 5. 已知属性与边界（**实验时必须心里有数**）

| # | 属性 | 影响 |
|---|---|---|
| **1** | ⚠️ **`SLAVE_IDS=1,2` 且 `REAL_DEVICE_SLAVE=1`** | **"温湿度只留真机"只对 1 号炉成立**；2 号炉的 `temp`/`humidity` **仍是仿真**，而**列名与表都相同** → 同表内两个物理量 |
| **2** | ⚠️ **接入层"一处不合格 → 整条拒收"** | **路径 A 下真机 2 点故障会让其余 7 个仿真点一起断档**。这是项目原有设计，工业口径上是「故障不隔离」（见 §7） |
| **3** | ⚠️ **桥写死 `COM3`** | **USB 重枚举成 COM4 后永久失联、不自愈** |
| **4** | ⚠️ **桥无开机自启** | 重启电脑后桥不会起 → 设备层**拒绝启动** → **9 点全停** |
| **5** | ⚠️ **桥与串口助手互斥** | 任何程序占用 COM3 即触发陈旧链路（已实测，见 §6 实验 E3） |
| **6** | ⚠️ **"读数冻结"无检测器** | 变送器活着但值卡住 → **静默入库**，无任何告警 |
| **7** | ⚠️ **网关心跳在读设备之前刷新** | 设备层没起来时**保持 healthy、零数据** → "**全绿零数据**" |
| **8** | ⚠️ **语义边界** | 真机测的是**环境**温湿度，而 `Temp`/`Humidity` 在环保口径上是**烟气**参数 —— 本部署只作**数据链路演示**，不作环保口径依据 |
| **9** | ⚠️ **缺少独立参照** | 现有验证全部**自证**（桥/网关/库同源），**没有第三方仪器对照** |

## 6. 实验清单（对着本基线做）

**设备层有两条不同的陈旧检测分支，日志与延迟都不同 —— 必须分开测。**

| # | 故障 | 代码路径 | 预期 | 状态 |
|---|---|---|---|---|
| **E1** | **桥进程死** | 设备层失败门限（**3 次 ≈ 6 s**）→ 写越界值 | 日志 `读真机失败（连续第 N 次）` | ✅ 已测（`b50c487`） |
| **E2** | **COM3 被占用** | 桥失败门限（**立即**）→ 桥写越界值 | 桥 `PermissionError(13)`；两条路径都拒收 | ✅ 已测（`bf81441`） |
| **E3** | ⭐ **变送器掉电 / A-B 断线**（桥活着） | **桥状态位=1**（**立即**） | 桥 `[1010, 3010, 1, …]`；两条路径都拒收 | ❌ **待测（本轮主角）** |
| **E4** | **读数冻结** | **无检测器** | ⚠️ **预计：静默入库、无告警** | ❌ 待测（**预计是缺口**） |
| **E5** | **USB 重枚举**（COM3→COM4） | 桥写死端口 | ⚠️ **预计：永久失联、不自愈** | ❌ 待测 |
| **E6** | **整机重启** | 桥无自启 | ⚠️ **预计：设备层拒绝启动、9 点全停** | ❌ 待测 |

**每次实验都要记录**：注错方式 / 起止时刻 / 桥寄存器 / 设备层寄存器 / 两层接入层日志 / 两张表的断档区间 / 恢复时刻。

## 7. 明确不在本基线范围内的（报告要写清）

- **路径 A 降级为注错工装**（日常走路径 B）是**建议**，尚未执行

## 8. 复现 / 回到本基线

```powershell
# 1. 回到本基线的代码
git checkout real-device-baseline-1

# 2. 起桥（宿主，必须先起 —— 设备层要读它）
python scripts/serial_bridge.py --port COM3

# 3. 起全栈
docker compose --profile plant2 --profile transmitter up -d --force-recreate

# 4. 验证（四条必须全过）
python -m pytest -q                 # 344 passed
python check_doc_links.py           # 退出码 0
docker ps --format "{{.Image}}" | Sort-Object -Unique   # cems-pipeline:latest 只出现一次
docker exec tdengine taos -d cems -s "SELECT LAST_ROW(temp), LAST_ROW(humidity) FROM cems.plant1_device1;"
```

⚠️ **`host.docker.internal` 是 Docker Desktop 的特性**；Linux 下需在 compose 里加
`extra_hosts: ["host.docker.internal:host-gateway"]`，否则容器读不到桥。
