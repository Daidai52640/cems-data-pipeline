# CEMS 全链路验收设计（数据血缘追踪）

> **本文是"验收怎么算过"的唯一准绳。**
> 每个数字都配**判据**与**复现命令**；每条判据都要能回答三件事：
> ① 什么算通过 ② 怎么复现 ③ 失败时怎么定位到层。

---

## 1. 为什么需要这份设计（先讲问题）

现有验证脚本有 23 个，**单点覆盖很强**（协议、仿真、告警、覆盖率、并发、故障演练），
但它们各验一段，**缺一条把"同一条数据"从头串到尾的链路**。后果是：

- 「网关发出了」有证据，「入库了」有证据，**但没人证明"发出去的就是入库的那条"**；
- 某一层**静默丢样本**时（例如接入层入库失败无副本、订阅端漏收），
  各段的脚本可能全绿 —— **因为没有一条数据被追踪到底**。

**→ 所以本文的核心判据是「数据血缘追踪」**：给一条数据打上**唯一标记**，
让它走完 `寄存器 → MQTT → 库 → 报表 → 告警 → 北向`，**每一跳都验"还是它、没被改、没丢"**。

## 4. ⭐ C19 数据血缘追踪（本次要新建的核心验收）

### 4.1 为什么用"标记法"而不是"数条数"

数条数只能证明"**数量**没丢"，证明不了"**是不是同一条**"：
- 两台设备混读时条数可以对；
- 入库失败后网关重发、另一条补上时**总数也对**；
- 值被算错（折算/单位）时**条数完全正常**。

**→ 必须给数据打**唯一标记**，然后逐跳比对。**

### 4.2 标记怎么造

用**一次性临时链路**（不污染现有两台设备）：

| 步骤 | 做法 |
|---|---|
| 1 | 起一套临时 **device + gateway + subscriber**，用**独立标签**：`TD_PLANT=trace`、`TD_DEVICE=run<N>`（N = 本次运行序号） |
| 2 | 标记的**唯一性**来自 `TD_DEVICE` —— 库里 `WHERE device='run<N>'` 就是本次那批，**绝不与真实数据混** |
| 3 | 从 **Modbus 寄存器**读一次"源值"（`Flow/...` 原始寄存器 ÷ scale）作为**源头基准** |
| 4 | 同时从 **MQTT 旁听**同一 topic，拿到**报文原文**（第 2 跳基准） |
| 5 | 查库拿**入库行**（第 3 跳基准） |
| 6 | 走报表 SQL 拿**聚合值**（第 4 跳） |
| 7 | 触发/读告警事件（第 5 跳） |
| 8 | 经 HJ212 出口编码 + 解码回原文（第 6 跳） |
| 9 | **逐跳比对**：`源 == 报文 == 库 == 报表（聚合一致）`，且**行数 == 应到数** |
| 10 | **清理**：删掉 `plant='trace'` 的行（TDengine 删行不删表，以 COUNT=0 为准） |

### 4.3 C19 的判据（必须逐条打印 PASS/FAIL）

| 子判据 | 断言 |
|---|---|
| **T1 源→MQTT** | 旁听到的报文条数 == 该窗口应发条数（周期 5 s） |
| **T2 MQTT→库** | 库里 `device='run<N>'` 的行数 == 旁听条数；逐条 `(ts, 9 测点)` **逐值相等** |
| **T3 值不被改** | 每测点 `库值 == 报文值`（容差 0，报文是十进制原样传输） |
| **T4 库→报表** | 该窗口报表 `n` == 库里条数；均值 == 库里 AVG（容差 1e-6 相对） |
| **T5 库→告警** | 构造一条越限样本 → 事件表有对应 `(point, start)`；不越限时不产生事件 |
| **T6 库→北向** | HJ212 编码→解码**往返一致**（含 CRC/转义/SM4 若启用） |
| **T7 重复投递幂等** | 同一条报文重发一次，库行数**不变** |
| **T8 端到端无丢失** | `应到 == 实到`，且**没有多余行**（`extra=0`） |

### 4.4 失败时的定位表

| 失败在哪一跳 | 说明问题在 |
|---|---|
| T1 失败（旁听数 < 应发） | 设备/网关采集层 |
| T2 失败但 T1 通过 | EMQX / 接入层（订阅、topic、QoS） |
| T3 失败 | 报文构造 / 解析 / 单位换算 |
| T4 失败 | 报表聚合 / 覆盖率口径 |
| T5 失败 | 告警判据 / 折算 |
| T6 失败 | HJ212 编解码 |
| T8 失败但 T2 通过 | 多设备混读 / 过滤条件 |

## 5. 验收执行顺序（从便宜到贵，失败即停）

| 阶段 | 内容 | 需要什么 | 时长 |
|---|---|---|---|
| **A. 静态** | `pytest`（211 项）+ 纯离线脚本（仿真三项、告警离线、码表向量） | 无 Docker | ~1 min |
| **B. 单链路** | `verify_pipeline_live.py --device device1/device2` | 10 容器 | ~1 min |
| **C. 契约** | 报表覆盖率、哨兵值、告警在线、幂等 | 10 容器 | ~3 min |
| **D. ⭐ 血缘** | **C19 全链路追踪（本文第 4 节）** | 10 容器 + 临时链路 | ~3 min |
| **E. 故障** | 断链补传、停 EMQX、TZ 错、断其中一台 | 10 容器 | ~10 min |
| **F. 并发** | 负载发生器 N=2/10/50 | 10 容器 | ~3 min |
| **G. 可靠性** | 备份恢复（按多设备重做） | 10 容器 | ~5 min |

**总时长约 25 分钟**；A~D 是"每次改动都该跑"的冒烟集，E~G 是"发版前跑"的完整集。

## 6. 已知边界（**验收不覆盖，且必须如实说明**）

| 边界 | 说明 |
|---|---|
| 非现场联调 | 全部为**本地回环 + 官方向量 + 开源对拍**，未接真实平台/真实仪表 |
| 接入层无副本 | **TDengine 写失败时该样本不在任何地方**（P1，已知边界，未修） |
| 仿真非真实工况 | 曲线由确定性数学模型生成，**不代表现场烟气特性** |
| 负载为合成 | `loadgen` 直发 EMQX，**绕过网关** → 测的是接入+存储层 |
| 单机部署 | 未验证多机/集群/HA |
| 网关采集上限 | 实测 ≈**1.05 条/秒/实例**（`POLL_INTERVAL` 压到 0.05 s 也不变） |
