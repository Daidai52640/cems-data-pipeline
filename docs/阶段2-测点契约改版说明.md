## 3. ⭐ 四个必须守住的概念（改版的核心价值）

### 3.1 量程 ≠ 限值 —— 别混（这是最容易搞错的一处）

| 概念 | 字段 | 谁用 | 触发什么 |
|---|---|---|---|
| **量程** | `low` / `high` | 接入层 `subscriber_to_td.py` | **拒收**超量程/负数/NaN（整条丢） |
| **限值** | `limit` | 达标判定/告警（**待实现**） | **报警**，但数据正常入库 |

**本表限值比量程小一两个数量级，这是正常的**：

```
SO2  量程 0~200 mg/m3   限值 35 mg/m3
     ↑ 仪器能测到 200     ↑ 但超过 35 就算排放超标
超量程 = 表坏了 → 拒收        超限值 = 排超标 → 告警
```

**⚠️ 只有量程没有限值，项目就演示不了"超标"这件事。**

### 3.2 ⭐ 折算值是**算出来的，不占寄存器、也不进库**

**这是库主明确的设计决定**，理由两条：

1. 折算值是**导出量**，存一份就必然有一天跟算出来的对不上（冗余会漂）
2. Modbus 保持寄存器省下来给真正的物理量

**公式**：

```
折算浓度 = 标干浓度 × (21 - 基准氧含量) / (21 - 实测氧含量)
```

代码实现：`points.to_reference_o2(value, o2)`，并且：

- ⚠️ **本公式的标准出处待库主核对**（我只拿到二次转述，没取到一手条文）
- ⚠️ 实测氧含量 **≥ 21%** → 分母 ≤ 0，折算无物理意义，**返回 `nan`**（不瞎除）

**烟测实测**（基准氧 6%）：

| 标干值 | 实测 O2 | 折算值 | 说明 |
|---|---|---|---|
| 35.0 | 6% | **35.00** | 等于基准 → 折算 = 标干 |
| 35.0 | 9% | **43.75** | 氧高（稀释）→ 折算**变大** |
| 35.0 | 3% | **29.17** | 氧低（富氧）→ 折算**变小** |
| 35.0 | 21% / 25% | **nan** | 分母 ≤ 0 |

### 3.3 ⚠️ 判定口径是**折算值**，不是标干值

**反例（烟测里真跑出来的）**：

```
SO2 标干 = 30.0 mg/m3 ，O2 = 9%
  → 按标干判：30.0 < 35  达标 ✅
  → 按折算判：37.50 > 35 超标 ❌
```

**⭐ 同一份数据，两种判法结论相反。这就是"为什么要折算"的实证**——
只报标干值，超标机组能"看起来达标"（用空气稀释烟气即可）。

### 3.4 `scale` 是**每个测点**自带的，不是全局一个值

Modbus 保持寄存器是 **16 位无符号（0~65535）**，`量程 × scale` 必须留余量。

**⚠️ 烟测实测抓到的两个真缺陷**（这就是引入 `scale` 字段的原因）：

| 测点 | 原写法 | 结果 |
|---|---|---|
| Flow | `200000 m3/h × 10` = 2,000,000 | **溢出** → 改 `scale=1`、量程 65000 |
| Pressure | `10000 × 10` 且**为负值** | **溢出 + 负值编不进无符号寄存器** → 改 kPa 表压 85~105 |

**已加导入期自检**：任何测点 `high × scale > 65535` → **`import` 时直接 `ValueError`**，不等到运行期。

## 8.5 仿真器落地 + 三个缺陷的修正（2026-10-01）

仿真器已由外派会话实现并落地：`src/device/simulator.py`（读数 = f(种子, 时刻) 纯函数式），
五项叠加 **基线 + 日周期 + 公共负荷耦合 + 独立缓慢漂移 + 小毛刺**，另加**偶发尖峰**（只在污染物上）。

随后做了一轮独立复核，发现并修掉 **3 个真缺陷**：

### 8.5.1 ⭐ `encode()` 的预量化：把 scale 变成了空操作

**原实现**：`int(round(round(value, 1) * scale))`

内层 `round(value, 1)` 先把真实值量化到 **0.1**，scale 只是把那个 0.1 的倍数放大
⇒ **任何 scale 的交付分辨率都恒为 0.1**。把 Dust 的 scale 从 10 提到 100 **等于没改**。

**实测**：2880 个采样里，`scale=10` 与 `scale=100` 的交付值**一个都不同**；
去掉内层预量化后，Dust 的 24 小时不同取值 **23 → 204**。

**已改为**：`int(round(value * scale))`（只量化一次，分辨率 = 1/scale）。

### 8.5.2 ⚠️ 基线区间不能用经验阈值猜，要按峰值预算倒推

**曾用**：`BASELINE_OF_LIMIT = 0.60~0.85` → 复核在 seed 75 下实测 SO2 **折算越限 20.5%**，
开尖峰时折算均值甚至到 **1.04 倍限值**（= 又变回"常年超标"，与修正目的相反）。

**峰值预算**（污染物，单位=限值比）：

| 分量 | 幅度 | 是否乘 span_ratio |
|---|---|---|
| 日周期 | 0.035×1.3 = 0.0455 | ✅ |
| 负荷耦合 | 0.012×0.25 = 0.003 | ✅ |
| 漂移 | 0.030×1.0 = 0.030 | ✅ |
| 毛刺 | 0.0025 | ✅ |
| **偶发尖峰** | **0.30~0.55** | ❌ **不乘**（这正是它能冲破限值的原因） |

不含尖峰的峰预算 ≈ 0.081；折算放大在 O2 低时实测最高约 1.5× ⇒ 基线上限 ≈ (1−0.081)/1.5 ≈ 0.61。

**现取值**：`BASELINE_OF_LIMIT = 0.50~0.68`（**多 seed 实测通过**，见下表），
`BASELINE_OF_RANGE = 0.40~0.70`（物理量，无判据参照）。

**多 seed 验证（24 h，30 s 采样，尖峰默认开）**：

```
折算均值/限值 的最大值 = 0.861（seed 75 的 SO2）   ← 必须 < 1.0
6 个 seed × 3 个污染物 = 18 组，全部达标
```

### 8.5.3 ⚠️ "是不是污染物"不能靠 `limit < high*0.5` 猜

**原规则**：`limit is not None and limit < point.high * 0.5`

**风险**：真实场景里 NOx 限值 200 mg/m3 + 量程 0~400（老标准/非超低排放行业）时，
`200 < 200` 为假 → **被静默判成物理量** → 基线改按量程锚定 → 复核实测 **NOx 100% 时间越限**。

**已改为显式声明 + 导入期校验**：

```python
LIMIT_ANCHORED_NAMES = frozenset({"Dust", "SO2", "NOx"})
# 声明为污染物的测点：必须真有 limit，且 limit < 量程上限 × 0.5，否则 import 时直接 ValueError
```

**⭐ 教训（与 8.5.1 同源）**：**"猜"出来的分类，改契约时就静默失效。**
凡是"这批里哪些是污染物"这种业务分类，都要**显式声明 + 导入期校验**，
而不是靠一个阈值去推断。

### ⚠️ 这轮验证抓到的 4 个真问题（全已修）

| # | 问题 | 根因 | 处理 |
|---|---|---|---|
| 1 | 大屏端口 5000 绑不上：`bind: An attempt was made to access a socket in a way forbidden by its access permissions` | 宿主机某进程（wegame）把 **5000 当临时源端口**且卡在 `CLOSE_WAIT`；netstat 里看不到 LISTENING | 宿主机映射改 **5001**（`WEB_HOST_PORT`），**保留 `BIND_ADDR`** 不暴露局域网 |
| 2 | 镜像构建失败：`No matching distribution found for pymodbus` | 清华源对 pip 返 **403**（宿主机同样 403），中科大/华为也不通 | `Dockerfile` 默认源改 **阿里云** |
| 3 | `failed to copy ... registry-1.docker.io` | BuildKit 要拉基础镜像层，而 docker.io 直连被拒 | 用**旧版构建器**（`DOCKER_BUILDKIT=0`）走本地缓存 |
| 4 | 大屏崩：`RuntimeError: 测点 velocity 缺少图表呈现配置` | 契约加了新测点，`POINT_PRESENTATION` 没跟上 | 补 `velocity` 配置 + 第 4 根 Y 轴 |

**⭐ 第 4 条是契约自检机制正常工作的证明**：一改契约，下游所有硬编码立刻暴露，而不是等到页面上少一条曲线才发现。
