真实工业项目全流程（以 CEMS 烟气在线监测为例）
五层架构 · 每层标注"干什么 / 用什么技术 / 今天 demo 对应" · 示意结构
⑤ 应用层（前端）
Web 大屏 · 管理后台 · 移动端 · 报表 · 告警通知（短信/钉钉/邮件）
技术：Vue/React + ECharts 今天对应：还没学到（后面做）
④ 平台层（服务端）
数据接入 → 解析校验 → 存时序库 → 告警引擎 → 对外 API
技术：TDengine/InfluxDB 时序库 + MySQL + 后端服务 今天对应：subscriber.py（收到打印 = 接入，还没存）
③ 传输层（网络）
4G/有线专网 · 心跳保活 · 断网续传
协议：HJ212（上报环保局）/ MQTT（私有平台） 今天对应：EMQX（MQTT 中转）
② 采集层（数采仪/边缘网关）★ 我现在的 gateway.py
协议转换 · 本地缓存（断网续传）· 边缘计算（折算/标定）· 打时间戳
技术：ARM 盒子/工控机 + 固件（Modbus/OPC UA → MQTT/HJ212） 今天对应：gateway.py（读→换算→加时间戳→发）
① 设备层（现场）
分析仪（SO2/NOx/O2/粉尘）+ 温压流传感器 → PLC/DCS
信号：4-20mA 模拟量 · Modbus RTU/TCP · RS485 今天对应：modbus_server.py（仿真设备）
贯穿全程的三条"流"
⬆ 数据流（上行·主力）
设备 → 采集 → 传输 → 接入 → 存储 → 展示
每5秒一条，量最大，我今天跑通的
⚠ 告警流（低频·要快）
平台检测超限 → 告警 → 短信/钉钉通知
pump-monitor 的 DingTalkNotifier 就是它
⬇ 控制流（下行·要可靠）
平台 → 网关 → 设备（远程校准/反吹/启停）
必须 QoS 2 或带确认，不能重复执行
