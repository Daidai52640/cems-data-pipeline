## 作废判定标准

一条报告被判为"对 3.0 失效"，必须给出**可核对的证据**，而不是凭时间新旧。本次用三类指纹核对：

| 指纹 | 含义 |
|---|---|
| `6 容器` | 6 容器时代的部署形态（现为 **8 基础 + 2 双设备 = 10**） |

| `cache.jsonl.sending` | 旧的在途文件方案（**v2.0.2 已改为唯一段名 `inflight-<seq>.jsonl`**） |

## 1. `TC-E2E-001-端到端数据一致性.md` → **作废**

| 项 | 内容 |
|---|---|
| **原结论** | ✅ PASS（8 测点全部一致，零精度丢失零列错位） |
| **作废原因** | ⭐ **测点契约已经变了**：该报告验证的是 **8 个测点**，而 `src/common/points.py` 现为 **9 个**（ADR-0001 改版）。**被测对象本身已经不是现在的东西**，整份结论无法沿用 |
| **指纹计数** | `8 测点` ×10、`6 容器` ×2 |
| **现行替代** | `docs/runbooks/全链路验收设计.md` 的 **C19 数据血缘追踪**（`scripts/verify_data_lineage.py`）：同样是"端到端一致性"，但改成**逐条时间戳级对账 + 零容差值比对**，比原有做法更严 |
| **日期** | 2026-09-16 |

## 2. `TC-E2E-003-全链路健康可观测.md` → **作废**

| 项 | 内容 |
|---|---|
| **原结论** | ✅ PASS（核心指标全部满足） |
| **作废原因** | ⭐ **被测的健康检查机制已被替换**：该报告的核心判据是"容器 healthcheck 能反映健康"。而后续发现 web 的 healthcheck 存在**结构性缺陷**（`except HTTPError: pass` → 500/502/404 一律判 healthy），已改为**数据新鲜度判据**（`/api/health` 按 `rows_last_1min` 与 `data_age_seconds` 返回 200/503）。**被测行为变了，结论自然失效** |
| **指纹计数** | `6 容器` ×12 |
| **现行替代** | `docs/runbooks/全链路验收设计.md` 契约 **C17「配置错误必须响亮」**；判据为"非法 tag → 拒绝启动"+"数据不新鲜 → `/api/health` 503"（均已实测） |
| **日期** | 2026-09-16（后续有零星更新，但判据未随之改变） |
