# 项目文档导航

> **这一页解决一件事：不管是谁，先看哪一套、从哪进。**
> **⚠️ 铁律：同一事实只写一份，另一套只做链接。** 不重复写两遍。
>
> **当前版本：3.0（双设备）** —— 两台设备 `plant1/device1` + `plant2/device2`，
> 部署形态为 **8 个基础容器 + 2 个双设备容器（`--profile plant2`）= 10**。
> 历史版本（v2.x 单设备、6 容器 / 8 测点）的**已失效报告**见 `legacy/`。

## 三、文档类型与写法约定

| 目录 | 类型 | 只写什么 | 写法要点 |
|---|---|---|---|
| `adr/` | **架构决策记录** | **决策与理由** | 背景 → 备选方案 → 决策 → **后果（含代价与局限）**。⚠️ **一份 ADR 一旦定稿不再改写**；决策变了就新加一份并标注取代关系 |
| `runbooks/` | **运维手册 / 台账 / 验收设计** | **怎么做 / 做过什么 / 怎么算过** | 命令可复现、带通过标准；台账按 `现象 → 排查 → 根因 → 修复 → 数据影响` |
| `reference/` | **事实与实测** | **约束与数字** | 数字必须来自实跑；**必须写测法、原始数据位置、误差来源** |
| `test-reports/` | **验收报告** | 测试目标、基线、通过标准、结论 | 保持既有格式；**不通过就写不通过**，并给出根因定性 |
| `legacy/` | **失效归档** | 只放**已被取代**的文档 | ⚠️ **必须配 `DEPRECATED.md` 写明"为什么作废"且原因可核对**；不作现行依据 |
| `evidence/` | **机器证据** | 原始产物 | ⚠️ **只读归档**，不在这里写结论；文件按来源分子目录 |
| `diagrams/` | 图形产物 | 生成物 | 源数据（json）与产出（html/png）一起放，便于重生成 |

## 四、⭐ 写文档的三条硬规矩

1. **结论必须能追溯到证据**
   每个数字后面要么给命令，要么给 `evidence/` 里的文件名。**不许出现"约为""大概"这类无法核对的数字。**

2. **区分"决策"与"事实"（最常见的错误）**
   - "我们选了全量备份，因为…" → **决策** → `adr/`
   - "实测恢复耗时 6.63~14.92 秒" → **实测** → `reference/` 或 `evidence/`
   - "容器时钟会漂" → **约束（事实）** → `reference/`
   ⚠️ **把事实写进 ADR、或把决策写进 reference，都会让人找不到东西。**

3. **局限与"没做到"必须单列一节**
   凡有实测，必有局限（样本量、负载条件、未验证的分支）。
   **不写局限的数字不可信**——这在本项目的多份文档里已是固定写法（见各文档的 §8/§10）。

4. **判据要跟着数据走，不能钉死历史时刻**
   ⚠️ 本轮验收实跑暴露的教训：多条判据写死了"某个历史小时"或"绝对事件数"，
   库一重建/基线一调就**必然误报**（甚至出现在空数据源上恒真）。
   **写判据时优先用"与数据无关的机制型断言"**（相对值、集合相等、逐条对账），少用绝对值。

## 五、证据归档约定（`evidence/`）

**命名**：保留生成时的原始文件名（便于与脚本输出对照）；**不要**为了好看重命名。

**⚠️ 只留数据，不留运行时日志**：容器 stderr 与旁听端的逐行确认属于**运行时日志**，
体积小但数量极大（曾占 `perf/` 的 84%），**不入库**；入库的是
**逐条对账的 csv / 汇总 json / 原始基准**（数字可复现即可）。

**⚠️ 一次性脚本与事故留档**：允许放到 `evidence/`，但必须在文件名或首行注明用途与"是否为一次性"。
（例：一次真实数据损坏与还原的修复脚本，属于**该留档的证据**，不是垃圾。）

## 六、什么时候该新增一份文档

| 情况 | 产物 |
|---|---|
| 做了一个**会影响后续设计**的选择 | 新增 `adr/NNNN-xxx.md` |
| 摸清了**一条以前不知道的约束**（如时钟会漂、broker 分片恢复有窗口） | 新增 `reference/xxx.md` |
| 真做了一次**故障演练 / 恢复演练** | 往 `runbooks/故障台账.md` 追加一条 |
| 测出了**一组会写进简历的数字** | 更新 `reference/性能与可靠性指标.md` |
| 发现**现有文档说错了** | 就地修正，并在提交信息里写明"修正了什么错" |
| 发现**整份文档的结论都不再适用** | **移入 `legacy/` 并写 `DEPRECATED.md`**（写明可核对的作废原因），**不要静默删除** |
