# ADR-0010 · 数据合理性判据（跳变 / 冻结）与「可疑 ≠ 无效」的区分

- 状态：**方案（待评审）**
- 关联：`docs/adr/0009-接入层逐点质量位.md`（本 ADR **复用**它的事件表与逐点机制）；
  `docs/架构与可维护性说明.md` §四 第 2 档
- 影响文件：`src/platform/subscriber_to_td.py`、`src/common/errors.py`（新增 `kind` 取值）、`docker-compose.yml`

---

## 1. 背景

ADR-0009 建立了**逐点质量位**机制，能表达"这个测点不可信"。但**判据只有量程**：

| 判据 | 现状 |
|---|---|
| 有限性（`NaN` / `inf`） | ✅ 有 |
| 量程（物理上不可能） | ✅ 有 |
| ⭐ **跳变率**（相邻样本突变） | ❌ **没有** |
| ⭐ **冻结**（值长期不动） | ❌ **没有** |

这两类**在真机上观测不到**（真机是正常工作的），但**可以在仿真测点上注入**。
而用户的目标是「**把真机故障实验的效果映射到其他仿真数据上，其他层一律按真实数据处理**」——
所以判据必须在**其他层（接入层）**实现，且**不区分真机 / 仿真**。

---

## 2. ⚠️ 最大的风险：**误报**（本 ADR 首先要处理的问题）

CEMS 稳态运行时，物理量**本来就很稳**。实测：`Temp` 在 `26.0 ~ 26.2 degC` 之间波动了 40 分钟。

若判据写成"**值不变就报警**"，会把**正常运行**判成故障 ——
而 ⭐ **误报比漏报更糟**：运维会直接**关掉它**，于是这个能力等于不存在。

**所以判据必须是「容差 + 持续」，不是「相等」**：

| 判据 | 定义 |
|---|---|
| **跳变** | `\|Δ\| > 量程宽度 × JUMP_RATIO` |
| **冻结** | 连续 `N` 个样本都落在 `[v0 − 容差, v0 + 容差]` 内，`容差 = 量程宽度 × TOLERANCE_RATIO` |

**都用"量程百分比"表达** → **不需要逐点配置**
（9 个测点量纲差 4 个数量级：`Flow ≈ 34000` vs `O2 ≈ 6.8`）。

---

## 3. ⭐⭐ 核心决策：**「可疑」≠「无效」**

| 判据 | 语义 | 处置 |
|---|---|---|
| 超量程 / `NaN` / `inf` | **物理上不可能** | ⭐ **不写该列**（丢） |
| **跳变大** | **可疑，但可能是真实工况突变** | ⭐⭐ **照常入库** + 留痕标为可疑 |
| **冻结** | **可疑，但可能是真实稳态 / 检修恒值** | ⭐⭐ **照常入库** + 留痕标为可疑 |

**为什么"可疑"不能丢**：
- 跳变可能是**真实的**（设备启停、工况切换）—— **丢掉等于掩盖真实事件**
- 冻结可能是**真实的**（停机、检修期间恒值）
- ⭐ 而"超量程"不一样：**物理上不可能**，丢掉是安全的

⚠️ **这是 ADR-0009 同一原则的延伸**：
ADR-0009 说"**无效**与**缺失**必须可区分"；本 ADR 说"**可疑**与**无效**也必须可区分"。

---

## 4. 落点：复用 ADR-0009 的事件表，**新增 `stored` 列**

显式表达处置，**让"丢了什么"和"标了什么但留着"各是一句 SQL**。

**`kind` 取值**（⚠️ 受 `NCHAR(10)` 限制，见 §6）：

| `kind` | `stored` | 含义 |
|---|---|---|
| `invalid` | `0` | 超量程 / `NaN` / `inf` |
| `missing` | `0` | 报文里没有这个测点 |
| ⭐ `jump` | **`1`** | 相邻样本突变（可疑，**值已入库**） |
| ⭐ `frozen` | **`1`** | 长期不变（可疑，**值已入库**） |

⭐ **加了 `stored` 之后**：
- 「**丢了什么**」→ `WHERE stored = 0`
- 「**标了什么但留着**」→ `WHERE stored = 1`

## 5. 配置

| env | 含义 | 建议默认 |
|---|---|---|
| `QUALITY_CHECK_ENABLE` | 总开关 | ⭐ 见 §7 的取舍 |
| `QUALITY_JUMP_RATIO` | 跳变阈值 = 量程宽度 × 该比例 | `0.25`（量程的 25%） |
| `QUALITY_FREEZE_SAMPLES` | 连续多少个样本不变算冻结 | `12`（≈ 1 分钟 @5 s） |
| `QUALITY_FREEZE_TOLERANCE_RATIO` | 冻结容差 = 量程宽度 × 该比例 | `0.005` |

⚠️ **这些默认值是"拍的"，没有标定** —— 标定手段就是 §8 的 **W4**。

## 6. ⚠️ 两个已实测的约束（都改变了本 ADR 的写法）

### ① `ALTER STABLE ADD COLUMN` **可用**（TDengine 3.3.6.13，实测）

```sql
ALTER STABLE probe ADD COLUMN stored TINYINT;   -- Query OK
DESCRIBE probe;                                 -- stored TINYINT 出现
SELECT ... FROM p1;                             -- 旧行 stored = NULL（向后兼容）
```
⚠️ 但 **`CREATE STABLE IF NOT EXISTS` 不会加列**（项目既有结论）——
**升级已存在的表必须显式 `ALTER`**，不能只靠建表语句。

### ② ⚠️ `kind` 列是 `NCHAR(10)`，新取值**必须 ≤ 10 字符**（实测踩到）

```
INSERT ... kind='suspect_jump'  ->  DB error: Value too long for column/tag: kind
```
⭐ **这就是为什么取值定成 `jump` / `frozen` 这种短名**，而不是 `suspect_jump`；
**人可读的解释放 `reason` 列**（它是 `NCHAR(200)`，够用）。

## 7. ⚠️ 待定的取舍：判据**默认开还是关**？

| 选项 | 利 | 弊 |
|---|---|---|
| **默认开** | 实验能直接用；真机真出异常也能抓到 | ⚠️ **误报会污染事件表**（虽然只留痕不丢数）；调参前可能有噪声 |
| **默认关** | 零风险 | ⚠️ "最终版本"里它是关的 → **实验证明不了它存在** |

⭐ **倾向：默认开，但阈值保守**（宁可漏报也不要误报），
且因为**只留痕不丢数**，"开着"的代价远小于"把真实数据丢掉"。

## 8. 验证判据（机制断言，不依赖具体数值）

| # | 判据 |
|---|---|
| **W1** | 注入**单点阶跃** → 该点**照常入库**，事件表 `1` 条 `kind=jump / stored=1` |
| **W2** | 注入**持续不变**（超过门限样本数）→ 该点**照常入库**，事件表 `kind=frozen / stored=1` |
| **W3** | 注入**超量程** → 该点**不入库**，事件表 `stored=0 / kind=invalid`（= ADR-0009 的 V1/V2，**回归**） |
| **W4** | ⭐⭐ **误报对照**：真机正常数据（稳态抖动 `26.0~26.2`）跑 ≥ 10 分钟 → 事件表**零新增** |
| **W5** | 判据**关闭**时，行为与"不实现本 ADR"**完全一致** |
| **W6** | 被标为可疑的点**仍然出现在报表/曲线里**（因为 `stored=1`） |

⭐ **W4 是本 ADR 最重要的一条** —— 它防的正是 §2 那个风险："**把正常运行判成故障**"。

---

## 9. 局限与不做（单列）

- ⚠️ **传感器缓慢漂移（硬件腐蚀）—— 本 ADR 不覆盖**：漂移是**缓慢**的，跳变与冻结**都抓不到**；
  需要**趋势检测**或**独立参照**（`docs/runbooks/真机接入.md` S3 的 ±0.5 degC 判据**一直未做**）
- **多测点交叉验证**（如 `O2` 与 `NOx` 的相关性）—— 不做
- ⚠️ **阈值没有标定** —— §5 的默认值是估计值，必须用 W4 在真实数据上校准
- ⚠️ **判据是"每设备的进程内状态"** —— 接入层重启后**前 N 个样本无法判冻结**（有冷启动窗口）
- ⚠️ **本 ADR 尚未实现**，§8 判据**全部未经实测**
